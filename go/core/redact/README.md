# redact

## What it answers

What text may leave the process: secrets, tokens and PII stripped from log
lines, telemetry payloads, LLM prompts and error reports. Which paths may be
touched is `go/core/scope`; how much and how fast an operation may run is
`go/core/breaker`.

## Use it when

- build a redactor in code → `redact.New().AddRule(id, pattern, replacement)`, `AddRules(rules...)`
- use the package default (gitleaks + Presidio loaded) → `redact.Default()`
- redact text → `Redactor.Apply(s)`, `Redactor.ApplyBytes(b)`
- audit without replacing → `Redactor.Scan(s)` (gitleaks detection); the regions `Apply` replaces → `Redactor.Spans(s)`
- rule internals and policy as data → `Redactor.Rules()`, `Rule.Spec()`, `Redactor.Policy()`, `NewFromPolicy(p)`, `CompileRule(spec)`
- default policy with no env override → `redact.NewEmbedded()`
- choose a strategy → `Redactor.SetReplacement(redact.Mask | Tag | Hash | Custom)`
- pass through a known-safe literal → `Redactor.AllowExact("AKIAIOSFODNN7EXAMPLE")`
- observe matches and counters → `Redactor.OnMatch`, `Redactor.OnAllowed`, `Redactor.Stats()`
- swap a rule corpus → `KIT_REDACT_RULES_PATH`, `KIT_REDACT_PII_RULES_PATH`

## Quick start

```go
clean := redact.Default().Apply(prompt)
resp, err := llmClient.Complete(clean)
```

## Contract

- The engine is stdlib `regexp` (RE2): linear-time by design, so backrefs and lookaround are absent. Upstream patterns using them are skipped silently by `loader.go::LoadGitleaks`; `NewFromPolicy` fails on them.
- Single pass: spans from every rule are found on the original text, overlapping and adjacent ones merged (earliest start wins, then the longest, then the rule added first), and replaced once. No rule sees another's placeholder.
- gitleaks v8.30.1 rule semantics: keyword gate, secret group (unset → the only group, else the whole match), inclusive entropy floor, global and per-rule allowlists. Two kit patches fix upstream allowlist entries that exempt live secrets.
- Two allowlist modes. `Scan` is detection: gitleaks semantics, substring regexes and stopwords. `Apply`/`ApplyBytes`/`Spans` fail closed: stopwords never exempt, a regex exempts only when it matches the whole target. Paths and commits never hold on text.
- Allowlists are literal, never regex, and match only in full. `Redactor.Allow` and the TOML `allowlist` key were substring-based redaction bypasses; `Allow` no longer compiles and the key is ignored, so migrate to `AllowExact` with the full literal.
- Replacement strategy is per-Redactor, not per-Rule. `Tag` reads each rule's preferred label from the TOML, else `<rule-id>`. A panicking `Custom` formatter is recovered and degraded to `Mask`.
- Allowlisted matches leave the process unredacted, fire `OnAllowed` and count in `Stats().Allowed`; unexpected growth there is a leak signal.
- `OnMatch` fires once per merged region, after allowlist filtering and before substitution, so it sees the matched secret. Count it, never persist it.
- `Default()` loads both corpora once via `sync.Once`: gitleaks first, then Presidio, with conflicting ids suffixed `-pii`. `contracts/redact-v1/rules.json` is that policy as data, embedded by the ports.
- `rules/presidio-pii.toml` is auto-generated by `internal/tools/vendor-presidio`; edit `curated.go`, not the TOML. Same upstream tag plus unchanged `curated.go` gives byte-identical output.
- A literal prefilter skips rules that cannot match before any regex runs; it never skips a rule that would match. A short field costs microseconds; a 4KB line still costs about 1.4ms with the full default policy, about 30x the 50µs budget. Measure before redacting multi-KB text per call on a latency-critical path; see [PERF.md](PERF.md).

## Neighbours

- `go/core/scope`: FS path guardrails, and the shared home of `rules/gitleaks-content.toml`.
