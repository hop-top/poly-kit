# rules

## What it answers

Where the gitleaks secret-detection corpus that `go/core/scope` and
`go/core/redact` share comes from, which upstream tag it is pinned to, and
how it is refreshed. Path policy logic is `go/core/scope`; matching and
replacement is `go/core/redact`.

## Use it when

- you need the raw rule TOML in another consumer: `rules.GitleaksContent` (rules plus nested allowlists)
- you need only the global path allowlist: `rules.GitleaksPaths`
- you bump the corpus: `make refresh-secret-rules`, then review the diff in this directory

## Quick start

```go
var doc struct {
    Rules []struct {
        ID string `toml:"id"`
    } `toml:"rules"`
}
if err := toml.Unmarshal(rules.GitleaksContent, &doc); err != nil {
    fmt.Println("err:", err)
    return
}
fmt.Println(len(doc.Rules) > 0, len(rules.GitleaksPaths) > 0)
// Output: true true
```

## Contract

- Vendored: `gitleaks-content.toml`, `gitleaks-paths.toml`, `LICENSE` from `github.com/gitleaks/gitleaks` at tag `v8.30.1`, commit `83d9cd684c87d95d656c1458ef04895a7f1cbd8e`, Apache-2.0. `SOURCES.md` in this directory is the provenance record.
- Generated by `internal/tools/vendor-gitleaks`; never edit the TOML by hand. Same tag yields byte-identical output, so a refresh with no upstream change is a no-op diff.
- Refresh target: `make refresh-secret-rules` (latest upstream tag), or `make refresh-rules` for this corpus and the Presidio one together.
- Both consumers read the same bytes through `//go:embed`; `KIT_REDACT_RULES_PATH` lets `go/core/redact` load a file instead.

## Neighbours

- `go/core/scope`: `SecretPaths()` consumes `GitleaksPaths`.
- `go/core/redact`: `LoadGitleaks` consumes `GitleaksContent`.
- `go/core/redact/rules`: the Presidio PII corpus, same layout.
- `internal/tools/vendor-gitleaks`: the generator.
